# PickLab：GitLab 提交遴选工具

在浏览器中浏览来源分支的提交历史，选中整条提交，调用 GitLab 服务端 Cherry-pick API 直接写入目标分支。连接、预览、试运行和正式遴选都通过 GitLab API；本机不克隆仓库，也不需要安装 Git。不会切换或修改你正在使用的本地工程。

首次使用个人令牌时，请参阅 [如何从 GitLab 获取令牌](HELP.md)；登录页也有可展开的简要步骤。

## 运行

需要 Node.js 20+。克隆仓库后先运行 `npm ci`，再运行 `npm start`。Windows 用户也可以直接双击 **`启动PickLab.cmd`**：首次启动会自动安装依赖，然后启动本机服务并打开浏览器。运行期间保留命令行窗口；关闭窗口即停止服务。

也可以在本目录手动运行：

```powershell
npm ci
npm start
```

## AI 分析提交

登录 GitLab 后点击顶部的 **AI 设置**，配置分析服务；无需先连接项目。服务、网关地址、模型和 Key 都在该页面管理：

- **OpenRouter**：填写自己的 OpenRouter Key，模型默认 `openrouter/auto`。一个 Key 可通过 OpenRouter 调用其支持的多家模型，实际可用模型、费用由 OpenRouter 账户决定。
- **LiteLLM**：填写 LiteLLM 网关地址（默认 `http://127.0.0.1:4000/v1`）和自己的虚拟 Key，或勾选“使用服务端环境变量 `LITELLM_API_KEY`”。模型名称可留空，PickLab 会从网关读取可用模型并选第一个；保存后点击“读取可用模型”，可以从完整下拉框选择其他模型，再次保存。也可手动填写管理员配置的模型别名。LiteLLM 网关管理员需要先配置上游模型及凭据。

使用环境变量时，请先在**运行 PickLab 服务的电脑和进程**中设置 `LITELLM_API_KEY`，再启动或重启 PickLab。例如在 PowerShell 中：

```powershell
$env:LITELLM_API_KEY = '你的 LiteLLM 虚拟 Key'
npm start
```

如果使用 Windows 双击启动文件，可在系统的“环境变量”设置中创建用户变量 `LITELLM_API_KEY`，然后重新打开启动文件。网页勾选后不会读取或显示该变量的值；服务端在保存配置时检查它是否存在。这个环境变量由同一台 PickLab 服务上的所有用户共用，因此共享部署时应确认是否允许共用该网关身份。

点击“保存 AI 配置”后，返回 **提交遴选**，选择并预览一条提交。提交页只显示当前 AI 配置、分析确认和结果；勾选“我同意将当前提交差异发送到所选 AI 服务”，再点击“分析当前提交”。AI 只分析提交，不会更改 GitLab 分支。每次分析都要重新勾选同意。发送内容最多约 3 万字符、30 个文件；超出时结果会提示差异已截断。二进制和 GitLab 未提供的差异无法供模型审阅。AI 输出只作辅助判断，执行遴选仍需 GitLab 的检查和你的确认。

手动填写的 AI Key 只保存在本机服务当前 GitLab 登录会话的内存中，不写入浏览器缓存或操作记录；退出登录或重启服务会清除。环境变量模式只在会话中记录 Key 来源，实际 Key 始终从服务进程环境读取。使用远端 LiteLLM 网关时，请确认网关地址；HTTP 地址会以未加密方式传输 Key 和提交差异。

接入使用 [Vercel AI SDK](https://ai-sdk.dev/docs/ai-sdk-core/generating-text)、[OpenRouter AI SDK Provider](https://ai-sdk.dev/providers/community-providers/openrouter) 和 [LiteLLM OpenAI 兼容网关](https://docs.litellm.ai/docs/proxy/docker_quick_start)。

打开 `http://127.0.0.1:4173`。首次使用时 GitLab 地址为空，请输入自己的 GitLab 站点或项目地址。成功登录后，浏览器只缓存这一个地址；成功连接项目后更新为项目地址，下次打开时自动填入。个人令牌不会被缓存。每位用户输入**自己的**个人访问令牌，点击“使用我的个人令牌登录”；页面会显示该令牌对应的 GitLab 用户名，退出后清除会话。登录成功后，页面自动按当前账号的分支推送记录查询最多十个不同项目，选中并连接最近推送的项目，接着加载分支提交；“刷新最近 10 个仓库”按钮可重新查询。也可以从下拉框选择其他项目，或手动输入完整项目地址并点击“连接项目”。管理员配置 OAuth 应用 ID 后，也可点击“使用 GitLab 账号登录”，使用自己的账号授权。**服务端遴选需要个人令牌的 `api` 权限**，原有仅含 `read_api` 与 `write_repository` 的令牌不足以执行写入 API；账号也必须有目标分支的写入权限。令牌仅保存在本机进程内存中，不写入代码或浏览器存储。服务仅监听 `127.0.0.1`。

## 配置 GitLab 登录

GitLab 管理员需先创建一个 **非机密 OAuth 应用**，启用 Authorization Code + PKCE，授予 `api`，回调地址设为 `http://127.0.0.1:4173/auth/callback`。将应用的 **Application ID** 配置在启动进程中（无需 Application Secret）：

```powershell
$env:GITLAB_BASE_URL = 'https://gitlab.example.com'
$env:GITLAB_OAUTH_CLIENT_ID = '管理员提供的 Application ID'
npm start
```

请将示例地址替换成你的 GitLab 站点。如修改 `PORT`，回调地址也须同步改为对应端口。未配置 OAuth 时，页面会保留个人令牌方式。每个用户使用自己的授权；退出登录会清除本机的登录会话。OAuth 访问令牌到期时服务会自动刷新。

工具不会跳过 TLS 校验。“允许 HTTP 连接”默认勾选，用户可以在登录前取消；使用 HTTP 时，授权码、令牌和仓库数据在本机到服务器的网络链路上不加密。建议使用可信的 HTTPS GitLab 地址。

## 使用流程

1. 连接项目并选目标分支、来源分支。来源分支默认优先 `master`，其次 `main`；目标分支会自动选成另一条分支，执行前仍请核对分支名称。
2. 提交历史默认只显示来源分支相对目标分支独有的提交；切换目标分支时会自动刷新。取消“仅显示来源独有提交”可查看来源分支全部历史。支持按标题或 SHA 搜索、作者筛选、时间排序和加载更早提交。点击一条提交后预览差异；勾选多条提交可加入批量队列。
3. 页面显示目标分支是否受保护、当前账号能否直接写入。单条操作先点击“检查整条提交”，GitLab API 的 `dry_run` 会显示可应用、冲突或空改动；检查通过后才能点击“直接遴选到目标分支”。本机不下载 Git 对象。
4. 单条遴选由 GitLab 在目标分支生成新提交，无需创建合并请求。新提交保留来源提交的作者和说明，提交 SHA 会改变。目标分支若在提交请求前变化，工具会要求重新加载。成功后，你的其他本地工程仍需在对应分支执行 `git pull`。
5. 批量队列最多 20 条，默认按旧到新排序，也可手动上移、下移。确认后逐条试遴选并写入目标分支；遇到冲突、空改动或其他错误即停止，页面列出已成功和未执行的提交。已成功写入的提交不会自动撤销。

每条遴选包含该提交的所有文件改动，包括二进制文件和重命名；是否支持合并提交由 GitLab 服务端决定。发生冲突或空改动的那一条不会写入目标分支；暂不提供网页内冲突解决。目标分支更新后，重新加载差异。GitLab 对超大提交的 API 差异可能有文件数量限制，预览可能不完整，但遴选依据提交本身。检查需要 GitLab 实例支持 Cherry-pick API 的 `dry_run` 返回值。

“来源独有提交”按 Git 提交历史的 `目标分支..来源分支` 范围筛选。已经遴选过的改动在目标分支上通常具有新的 SHA，仍可能先显示在列表里。点击“检查整条提交”后，如果 GitLab 判定遴选结果为空，页面会提示目标分支可能已包含改动或后续提交覆盖了内容，并将该提交从当前筛选列表隐藏；关闭筛选仍可查看。这项标记只保存在当前页面中，刷新页面后需要重新检查。

## 操作记录

单条与批量操作的结果会按 GitLab 账号和项目分别显示在页面下方，包含来源 SHA、目标分支、新 SHA 与 GitLab 提交链接；失败的批量步骤也会记录。记录保存在运行 PickLab 的电脑上：Windows 默认 `%LOCALAPPDATA%\PickLab\operations.json`，可通过 `PICKLAB_DATA_DIR` 环境变量修改目录。记录不包含访问令牌，最多保留 2000 条；刷新页面或重启服务后仍可查询。若记录写入失败，页面会提示，但已成功的 GitLab 提交不会回滚。

## 变更落地看板

连接项目后，使用主区域的“提交遴选 / 变更落地”页签切换到独立看板。看板按所选分支读取 GitLab 提交历史，每次加载 50 条，可按标题、作者或 SHA 筛选已加载的提交并继续加载更早提交；点击提交即可查询。也可输入完整 SHA；操作记录中的“查看落地”可直接打开看板。看板先核对原提交及 PickLab 记录的新 SHA；若没有记录，还会在项目最近 500 条提交中查找标题相同且增删内容一致的提交，并用 GitLab 的引用接口确认该提交属于哪些分支。查询只读，不会写入分支。看板会显示“原提交存在”“遴选提交存在”“同等提交存在”“近 500 条未检出”或“暂无法验证”，并展示找到的新 SHA。未检出不等于代码一定不存在；提交可能更早、改了标题或在落地时修改过补丁。即使检出提交，后续提交仍可能再次修改或撤销其内容。

GitLab 官方文档：[Commits API](https://docs.gitlab.com/api/commits/)、[Branches API](https://docs.gitlab.com/api/branches/)。
